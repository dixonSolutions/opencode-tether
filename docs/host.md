# Host setup

The host is a single Rust binary. It serves the opencode-tether web app, starts and supervises an `opencode serve` process, proxies the opencode HTTP API (including SSE), proxies PTY WebSockets, and puts one login in front of everything.

It is the recommended way to use opencode-tether remotely. You can also skip it and point the app directly at `opencode serve`; see [Remote mode](#remote-mode).

## Requirements

- Linux x86_64, aarch64, or armv7 (the release binaries are static musl builds).
- `opencode` installed on `PATH` and already authenticated for the user that runs the host.
- A user account that can read the projects opencode works on.
- Port 4096 (or your chosen port) reachable from the devices you use.

## Quick start

```sh
opencode-tether init
opencode-tether serve
```

`init` prompts for a username and password, hashes the password with Argon2, generates a cookie secret, and writes the config (default `/etc/opencode-tether/config.toml` as root, `~/.config/opencode-tether/config.toml` otherwise).

Open the printed address. You should see the sign-in screen. If opencode starts successfully, the login screen reports its version.

### User service (recommended)

opencode must be able to read your projects, so run the host as yourself:

```sh
opencode-tether init --config ~/.config/opencode-tether/config.toml
opencode-tether service install --user
systemctl --user daemon-reload
systemctl --user enable --now opencode-tether
loginctl enable-linger "$USER"
journalctl --user -u opencode-tether -f
```

### System service

`opencode-tether service install --system` writes `/etc/systemd/system/opencode-tether.service`. If you run it with `sudo`, it uses `SUDO_USER` as the service user and points `HOME` at that user's home. Review the unit before enabling it.

```sh
sudo opencode-tether service install --system
sudo systemctl daemon-reload
sudo systemctl enable --now opencode-tether
```

## Configuration

`opencode-tether init` produces a working config. The annotated example is [`packaging/config.example.toml`](../packaging/config.example.toml).

### `[server]`

| Key | Meaning |
| --- | --- |
| `bind` | Listen address, default `0.0.0.0:4096`. Use `127.0.0.1:4096` behind a local reverse proxy. |
| `username` | The only login username. |
| `password_hash` | Argon2 hash generated by `init`. Never put a plain password here. |
| `cookie_secret` | 64 hex characters, generated by `init`. Changing it signs everyone out. |
| `secure_cookies` | Set `true` when the public URL is HTTPS. |
| `public_url` | Optional canonical URL. Used for CORS/origin checks and HTTPS cookie detection. |
| `allowed_origins` | Extra browser origins allowed for CORS and WebSocket auth. Native builds use `tauri://localhost` and `http://tauri.localhost`. |
| `session_days` | Cookie lifetime, default 30. |

### `[opencode]`

| Key | Meaning |
| --- | --- |
| `command` | Command used to start opencode. Supports `{port}`, `{hostname}`, `{bind}`, `{url}`. |
| `port` | Loopback port for the upstream. Default `5191`. |
| `hostname` | Upstream host. Default `127.0.0.1`. |
| `autostart` | Start the command. Set `false` to proxy an existing server. |
| `startup_timeout_secs` | How long to wait for `/global/health` before continuing. |
| `health_interval_secs` | Background health poll interval. |
| `working_dir` | Optional working directory for the child process. |
| `username` / `password` | Optional Basic auth for an upstream that already has HTTP auth. |
| `env` | Extra environment variables for the child. |

The default command is:

```toml
command = "opencode serve --hostname 127.0.0.1 --port {port}"
```

The host keeps upstream auth off the last mile: the browser never receives the upstream credentials, and the host strips its own `Authorization`/`Cookie` headers before forwarding.

### `[web]`

- `root` — optional path to a built web app. Leave unset to use the UI embedded in the binary.
- `title` — document title.

### `[update]`

- `repo` — GitHub repository used by `opencode-tether update`.
- `channel` — reserved for future channels.
- `check_on_start` — reserved.

## HTTPS

Do not expose a plain HTTP host to an untrusted network. Put it behind a TLS terminator:

**Caddy**

```caddyfile
tether.example.com {
    reverse_proxy 127.0.0.1:4096
}
```

Then set `bind = "127.0.0.1:4096"`, `public_url = "https://tether.example.com"`, and `secure_cookies = true`.

**Tailscale**

```sh
tailscale serve --bg 4096
```

or use the host's tailnet address directly and keep it off the public internet. The app works fine over HTTP on a trusted tailnet.

**nginx** needs `proxy_buffering off;` and a long read timeout for SSE and WebSockets.

## Remote mode

If you do not want the host:

1. Run `opencode serve --hostname 127.0.0.1 --port 4096` (or any address).
2. Give the app the address, plus the opencode username/password if configured.
3. Make sure the device can reach the port.

Remote mode still gets sessions, chat, tools, permissions, models, commands, todos, diffs, and terminal. The host adds: one login page, the embedded app, health reporting, same-origin delivery, upstream auth isolation, and WebSocket ticket handling.

Direct remote mode is not recommended on the open internet. Put opencode behind a VPN, SSH tunnel, or reverse proxy with TLS.

## Operations

```sh
opencode-tether status --config /etc/opencode-tether/config.toml
opencode-tether doctor --config /etc/opencode-tether/config.toml
journalctl --user -u opencode-tether -f
sudo systemctl restart opencode-tether
```

### Updating

```sh
sudo opencode-tether update          # checks GitHub releases, verifies SHA-256, replaces the binary
sudo systemctl restart opencode-tether
```

Flatpak installs are updated with `flatpak update ai.opencode.tether`, not with `opencode-tether update`.

### Troubleshooting

- **401 everywhere**: wrong host username/password, or the browser has a stale cookie. Clear the site data or use the host login again.
- **`upstream did not become ready`**: check `opencode` is installed, authenticated, and can bind the upstream port. The default command is logged at startup.
- **`Address already in use`**: another host is already running. `opencode-tether status` will tell you.
- **SSE reconnects**: a proxy is buffering. Disable buffering and raise read timeouts.
- **WebSocket terminal fails**: a proxy is not forwarding `Upgrade` headers. Allow WebSockets on the route.
- **Android cannot reach the host**: use the LAN/tailnet IP, not `127.0.0.1`, unless you are using `adb reverse`.
